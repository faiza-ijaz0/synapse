# 04 — Implementation Roadmap

Status: **Approved** · revised 2026-10-28 after Phase 1 review

Each phase ends with **exit criteria that have been verified by running them**.
A phase isn't done because its code exists. It's done when its checks pass.

**Priority (owner decision, 2026-10-28):** the core first. That means the shared
TypeScript foundation, environment validation, the database, the codebase
analysis CLI, and API testing. Website audits, test-result intelligence, and
optional local AI follow once the core works.

## Ordering rationale

- **CLI before the egress guard:** codebase analysis has no network attack
  surface beyond the authenticated `/ingest` endpoint, so it delivers value
  sooner. API testing then introduces `net-guard`, the most security-critical module.
- **The web UI comes after the core APIs,** so screens are built against real
  endpoints rather than mocks.
- **Website audits reuse `net-guard`.** The Chromium proxy applies a policy
  that was already tested in Phase 4.
- **AI comes last.** By design, nothing depends on it.
