# ADR-0003: PostgreSQL 17 + Prisma 7 with versioned migrations

Status: Accepted · 2026-10-28

## Context

The system needs relational history (runs → findings), JSON payloads, strong
constraints, and indexes. PostgreSQL 17.11 is already installed and running locally.

## Decision

PostgreSQL with Prisma ORM **7.10.1** (stable), using `@prisma/adapter-pg` over
`pg`. Migrations are generated by `prisma migrate dev`, committed, and applied
by `prisma migrate deploy`. The app uses a non-superuser `synapse` role. Large
raw tool outputs go to `SYNAPSE_DATA_DIR`, and rows keep structured summaries
plus a path.

Pinning note: on 2026-10-28 the npm `latest` dist-tag for `prisma` pointed to
`8.0.0-rc.28`, a release candidate, so versions are pinned exactly and not
taken from `latest`.

## Consequences

- \+ Typed queries, reviewed SQL migrations, and Postgres enums, jsonb, and
  partial indexes.
- − Some queries (trend aggregations) may need `$queryRaw` with typed results.
- − Prisma major upgrades need care. Prisma 8 will be evaluated once it's stable.

## Alternatives

- Drizzle: a strong alternative, lighter and SQL-first.
- Kysely.
- SQLite: simpler to install, but weaker concurrency for API+worker and fewer
  index and enum features.

The proposed stack named Prisma, and nothing found argues against it.
